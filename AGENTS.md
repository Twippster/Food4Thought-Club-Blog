# Base44 Dev Notes — Food4Thought

## What this is

A pnpm monorepo (Node 22, pnpm 10, TypeScript 5.9) with three workspace areas:

- `artifacts/food4thought` — Vite + React 19 web app (the public preview on port 3000)
- `artifacts/api-server` — Express 5 API (esbuild-bundled, runs on port 5000 inside the compose network)
- `lib/db` — Drizzle ORM + PostgreSQL schema; `lib/api-spec`, `lib/api-zod`, `lib/api-client-react` are the OpenAPI → Zod → React-Query codegen chain

## Why the app failed to start before

Both `artifacts/food4thought/vite.config.ts` and `artifacts/api-server/src/index.ts` **throw at module load** if their required env vars are missing:

- Vite requires `PORT` and `BASE_PATH` (throws synchronously on import).
- The API server requires `PORT` and `DATABASE_URL` (throws on import / DB pool init).

Without these the processes crash before serving anything. The Base44 compose file (`docker-compose.base44.yml`) supplies them.

## How it runs here (single origin)

- Only port 3000 is public. The Vite dev server proxies `/api` → `http://api:5000` so the frontend's relative `/api/...` requests (generated by orval, no `setBaseUrl` call) resolve on one origin. The proxy is gated on `API_PROXY_TARGET` so it is inert on Replit.
- PostgreSQL runs as a compose service with generated credentials (`postgresql://f4t:f4t@db:5432/f4t`).
- A one-shot `migrate` service runs `drizzle-kit push` to create tables before the API starts.
- A one-shot `deps` service runs `pnpm install --frozen-lockfile` so `api`/`web` share one `node_modules` with no concurrent installs.

## Startup order

`db` (healthy) → `deps` (completed) → `migrate` (completed) → `api` (healthy) → `web`

The API server seeds five stories on startup (`seedStories` in `artifacts/api-server/src/lib/seed.ts`); seeding is idempotent (`onConflictDoNothing` on slug).

## pnpm version

pnpm 10 is required because `pnpm-workspace.yaml` uses `minimumReleaseAge: 1440`, a pnpm 10 feature. The lockfile is version 9.0 (compatible). Always install with `--frozen-lockfile`.

## Health endpoints

- API: `GET /api/healthz` → `{ status: "ok" }`
- Web: `GET /` (Vite dev server)

## Gotchas

- `lib/integrations/*` is listed in `pnpm-workspace.yaml` but the directory does not exist; pnpm ignores the unmatched pattern.
- The API server's `dev` script builds with esbuild then runs the bundle (no live reload). Restart the `api` service after editing server code. The Vite frontend does hot-reload.
- `@replit/vite-plugin-cartographer` and `@replit/vite-plugin-dev-banner` only load when `REPL_ID` is set, so they are inert here. `@replit/vite-plugin-runtime-error-modal` always loads and is harmless.
